# AlphaCode security-assessment capability baseline — 2026-11-14

## Scope of this baseline

Repository snapshot: Git `HEAD` `96891d83266e728596e203e38ae05403fe368209` (working tree was already dirty before this pass). This is a bounded source/test/docs review, not a full audit, an active assessment of a deployed target, or an independent product evaluation. Existing user changes were preserved. The XBOW feature list is treated as a public requirements reference supplied in the request; no XBOW account, binary, test access, or controlled head-to-head run was available.

Status vocabulary is kept separate by dimension:

- **Implementation:** `implemented`, `partially implemented`, `not applicable`.
- **Evidence:** `tested` means an executable test was run for that specific claim; `untested` means no such run in this pass. Existing tests that were not rerun are identified as such.
- **Independent verification:** `independently verified` is reserved for an independent evaluator or separately implemented oracle. This pass did not independently verify product behavior.
- **Blocked:** a prerequisite such as program access, controlled identities, or direct competitor access is unavailable. It is not a negative result.

## Prioritized gaps

1. Close the mismatch between structured investigation records and live execution: ranked, in-scope hypotheses should consume actual tool observations and explicit shared budgets, while preserving blockers and distinguishing rejection from disproof.
2. Extend the loopback benchmark beyond one IDOR-like root-cause family to repaired variants, false-positive traps, auth/session/tenant controls, rate limits/timeouts, interrupted writes, malformed/adversarial responses, canary redaction, fix retests, and availability/scope oracles. Keep held-out fixtures separate from development-visible answers.
3. Build and test a durable assessment lifecycle with immutable policy/revision references, protected resources, per-target limits/windows, cancellation, evidence expiry, audit events, and a retest state that requires a new deployed observation.
4. Add controlled multi-identity artifact isolation and an end-to-end proof matrix for read/write/privilege effects; keep unsupported or cross-tenant tests blocked when identities are unavailable.
5. Add dashboard/report/export and CI retest workflows only after their typed state contracts and safe cancellation behavior have regression coverage.
6. Run matched, multi-trial comparisons only with direct XBOW evidence, pinned revisions/models/configurations, equivalent permission/budget, held-out fixtures, raw artifacts, and confidence intervals. Otherwise compare AlphaCode only against the publicly described requirements reference.

## Score and claims

No aggregate score is calculated. The requested weighted score requires category-level passing evidence across a representative benchmark, which this repository review and five runner self-tests do not provide. Engineering work, source-level controls, fixture behavior, deployed impact, independent verification, and competitor performance are different evidence classes. This baseline establishes neither a 10/10 score nor superiority over XBOW.
